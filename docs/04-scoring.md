# 04 — 判分方法（Scoring Spec）

**這份是目前實作的權威說明。** `01-game-design.md` 是最初的設計構想，部分細節已隨實測調整，以本文為準。
所有數值集中在 `app/src/game/balance.ts`，程式碼在 `app/src/game/scoring/`。

---

## 全景：一次朗讀怎麼變成傷害

```
你的聲音
  → ① 語音辨識（Web Speech API，回傳最多 5 組候選）
  → ② 挑出最接近題目的那組候選
  → ③ 正規化（數字轉換、繁簡、大小寫、縮寫）
  → ④ 逐字對齊 → 三色標記 + 找出多唸的字
  → ⑤ 算出正確率 0–100%
  → ⑥ 換算成傷害，打在對方身上
```

---

## ① 語音辨識與 ② N-best 候選

辨識引擎內建語言模型，會**擅自把聽到的音修正成通順的詞**——這對繞口令是致命傷（唸「會發黑」被改成「揮發」、「板在板凳上」被改成「綁在」）。Web Speech API **沒有任何參數可以關掉這個行為**。

緩解手段：向引擎要求每段最多 **5 組候選**，把各段候選的所有組合（上限 240 組）都算一次分，**取正確率最高的那組**。正確答案常常還留在第 2、3 名。

> 若計分採用的不是引擎第一名，練習模式會顯示「🔎 引擎原本聽成 X，已改用較接近題目的候選計分」。
>
> **這是緩解不是根治**：候選裡完全沒有正確答案時就無解。根治需改用發音評分（見 `05-online-sop.md` 的 Azure 方案）。

## ③ 正規化（比對前的前處理）

| 處理 | 說明 | 例 |
|------|------|-----|
| 阿拉伯數字 → 文字 | 辨識常把數字回傳成阿拉伯數字，不轉換會被當成非中文字濾掉而整題判錯 | `44` → 四十四、`800` → 八百、`104` → 一百零四、`6` → six、`33` → thirty three |
| 中文：只取漢字 | 標點、空白不列入計分 | 「四是四十，是十」→ 四是四十是十 |
| 英文：小寫化、去標點 | | `Peter Piper picked!` → peter piper picked |
| 英文：縮寫展開 | | `they're` → they are |

## ④ 逐字對齊與三色標記

先用**編輯距離（Levenshtein）對齊**題目與辨識結果，讓漏字、多字不會造成整串位移。對齊後每個「題目的字」給一個顏色：

### 中文（以「字」為單位，比對拼音）

| 顏色 | 條件 | 得分 |
|------|------|------|
| 🟩 綠 | 拼音**含聲調**完全相同 | 1.0 |
| 🟨 黃 | 拼音相同但**聲調錯**，或屬於**近音**（見下） | 0.5 |
| ⬜ 灰 | 其他、漏唸 | 0 |

**近音規則**（反映常見口音，避免一點腔調就被判死）：

- 平翹舌不分：`zh/ch/sh` ↔ `z/c/s`
- n / l 不分、r / l 不分
- 前後鼻音不分：韻尾 `ng` ↔ `n`（ㄤ↔ㄢ、ㄥ↔ㄣ）

> 例：「娘」(niang) 被聽成「量」(liang) → 近音 → 黃（0.5），而不是直接判錯。
> 反過來，「天」(tian) 對「狗」(gou) 正規化後仍不同 → 灰。

⚠️ **副作用**：因為 ㄢ↔ㄤ 視為近音，「板」(ban) 與「綁」(bang) 會判黃而非灰。這是「照顧口音」與「嚴格判定」之間的取捨，目前偏向前者。

### 英文（以「詞」為單位）

| 顏色 | 條件 | 得分 |
|------|------|------|
| 🟩 綠 | 正規化後完全相同 | 1.0 |
| 🟨 黃 | 在同音詞表內（there/their/they're、to/too/two、sea/see、wood/would、for/four…） | 0.5 |
| ⬜ 灰 | 其他、漏唸 | 0 |

### 多唸的字（插入）

對齊時若出現「題目裡沒有、卻唸出來」的字，會被列為**多唸**，每個扣 **0.5 分**。

> 「紅鳳凰」唸成「**粉**紅鳳凰」→ 三字全綠(3.0) − 多唸1字(0.5) = 2.5 → **83%**
> 「紅鳳凰」唸兩遍 → 3.0 − 1.5 = 1.5 → **50%**

結算畫面會列出多唸了哪些字。

## ⑤ 正確率

```
正確率 = max(0, (三色得分總和 − 多唸字數 × 0.5) ÷ 題目字數)
```

- 範圍 0–100%，下限為 0（不會變負數）
- **≥ 95% 判定為 PERFECT**

---

## ⑥ 傷害公式

```
傷害 = round(20 × 正確率²)          ← 基礎
     + round(5 × 剩餘時間比例 × 正確率)  ← 早唸完加成
     + (PERFECT ? 5 : 0)              ← 完美加成
```

- 用**正確率的平方**：唸得爛幾乎沒傷害、唸得好差距拉開，避免搶快亂唸
- **剩餘時間比例**以「最後一次偵測到你出聲」計算，所以提早唸完自然有加成，不需要按任何按鈕
- 這就是為什麼**兩個人同樣 100% 卻可能打出 25 與 26**——差在早唸完加成。成績卡會列出組成（`基礎 20 + 早唸完 1 + 完美 5`）

## 血量與勝負

- 雙方初始 **HP 100**，**血量可以是負數**
- 一回合內雙方各唸同一題一次；**先攻一唸完就立即結算扣血**
- **後攻即使已被打到 0 以下，仍要完成他這一擊**（拚死還手）
- 回合結束才判定勝負：

| 情況 | 結果 |
|------|------|
| 只有一方 HP ≤ 0 | 另一方獲勝 |
| **雙方都 ≤ 0（雙殺）** | 比**全場加權平均正確率**，高者勝 |
| 雙殺且加權正確率差 < 2% | 平手 |

**加權平均正確率** = `Σ(該次正確率 × 該次傷害) ÷ Σ傷害`——以造成的傷害為權重，所以關鍵回合唸得好比較有份量。
血量多寡在雙殺時**完全不影響**勝負（-3 不會贏過 -4）。結果頁會完整說明判定過程。

## 時間

```
作答秒數 = max(4, round((題目 timeLimitSec + 5) × 0.5))
```

`countdownScale = 0.5` 是實測後把時間砍半的結果，改這一個數字就能整體調鬆緊。

回合節奏（全自動，不需按任何按鈕）：

| 階段 | 秒數 |
|------|------|
| 擲硬幣 | 3 |
| 回合開場（宣告先攻／**選道具**／已顯示題目） | 10 |
| 看題 | 3 |
| 作答 | 依題目 |
| （換人：看題 3 → 作答） | |
| 回合結算 | 5 |

## 道具

開局每人拿到**四種各一個、不重複、兩邊完全相同**——勝負取決於用的時機而非運氣。每回合最多用一個，在回合開場的 10 秒內選擇（此時題目已公開，可看題再決定）。

| 道具 | 效果 | 對象 |
|------|------|------|
| ⏱️ 時間掠奪 | 對手作答時間 −2 秒（不低於 3 秒） | 對手 |
| 🔊 噪音干擾 | 對手朗讀時播放三聲部人聲（碎念／唱歌／大笑） | 對手 |
| 🕳️ 文字遮蔽 | 對手看到的題目遮住 25%（**只遮顯示，判定不變**） | 對手 |
| 🧛 吸血 | 本回合造成多少傷害就回復多少（上限 100） | 自己 |

吸血 + 可負血量 = 翻盤機制：被打到 −8 時吸血打出 20 傷害就能回到 +12 活下來；但只打出 8 就還是 −12 陣亡。**吸得回來是實力，因為吸多少完全取決於你唸得多好。**

## 已知限制

1. **辨識引擎的腦補**是最大誤差來源，N-best 只能緩解。根治要換發音評分架構（Azure）。
2. 中文近音規則偏寬鬆，「板/綁」這類前後鼻音差異會判黃而非灰。
3. 若辨識引擎自己多吐了字（把雜音辨識成詞），會被當成多唸而扣分。
4. Web Speech 僅 Chromium 系瀏覽器可用，且辨識在雲端進行需要網路。Brave 的隱私防護會擋住它。
