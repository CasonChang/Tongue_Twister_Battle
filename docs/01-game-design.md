# 01 — 遊戲設計（Game Design）

本文件定義遊戲規則本身，不談技術實作。實作方式見 `02-architecture.md`。

文中標示 **【決定】** 的地方是規劃時替業主做的預設決定，附有理由與替代方案；業主可在 `03-implementation-plan.md` 的「待確認清單」一次檢視所有決定。

---

## 1. 遊戲模式

| 模式 | 說明 |
|------|------|
| **單機對戰（hot-seat）** | 兩人共用同一台裝置與同一支麥克風，輪流唸題。不需要網路。 |
| **連線對戰** | 兩人各自用自己的裝置，透過房間代碼配對。對戰中可即時聽到對方的聲音。 |

**【決定】單機對戰＝同裝置兩人輪流，不做 vs AI。**
理由：hot-seat 不需要額外設計 AI 難度曲線與 TTS 唸題，卻能完整驗證核心玩法；架構上已把「對手」抽象化（見 02 文件），之後要加 vs AI 是純新增、不需改動。替代方案：第一版就做 vs AI（成本高、且 AI 唸繞口令的娛樂效果存疑）。

---

## 2. 一場對戰的完整流程

```
進入對戰
  └─ ① 嗆聲階段（10 秒）：雙方麥克風全開，自由嗆聲
  └─ ② 決定先後攻：系統擲硬幣（隨機），顯示動畫
  └─ ③ 回合迴圈（直到一方 HP ≤ 0）：
        ├─ 出題：系統從題庫隨機抽一題（雙方看到同一題）
        ├─ 道具階段（5 秒）：雙方可各使用一個道具，作用於對方本回合的朗讀
        ├─ 先攻朗讀：倒數計時開始 → 先攻者唸題 → 語音辨識 → 計算正確率
        │             → 立刻對後攻者造成傷害（含攻擊演出）
        ├─ 後攻朗讀：同一題，換後攻者唸 → 同樣計算 → 對先攻者造成傷害
        ├─ 回合結算：顯示雙方本回合正確率、傷害、剩餘 HP
        └─ 交換先後攻，進入下一回合
  └─ ④ 結果畫面：勝負、全場數據（平均正確率、最高單次傷害…）
  └─ ⑤ 賽後選項：再來一局（雙方都同意才開始）／ 離開房間
        （此時雙方麥克風重新全開，可以講垃圾話）
```

### 2.1 先後攻要不要交換？——**【決定】每回合交換。**

理由：後唸的人剛聽過對方唸一次，等於多了一次「試聽」，同時也承受「知道要贏對方多少」的壓力——不論這是優勢還是劣勢，固定不換都會讓其中一方整場吃虧或占便宜。每回合交換讓兩邊平均承擔，規則也最好懂。
替代方案：(a) 整場固定（不建議）；(b) 上一回合輸的人先攻（追趕機制，可列為之後的選項開關）。

### 2.2 計時規則

- 每題附帶 `timeLimitSec`（題庫欄位，見 §6），以「正常語速約 10 秒唸完」的題目為主，倒數預設為 **題目秒數 + 5 秒緩衝**（例：10 秒題 → 15 秒倒數）。
- 倒數歸零時強制收音，以當下已辨識出的內容計算正確率（沒唸到的部分視為錯誤）。
- 玩家唸完可以按「完成」提早結束（或由系統偵測靜音 2 秒自動結束），**提早完成有時間加成**（見 §3.2）。

### 2.3 麥克風開關規則（單場對戰內）

| 階段 | 我方麥克風 | 我聽得到對方嗎 |
|------|-----------|----------------|
| 嗆聲階段 | 開 | 聽得到 |
| 我朗讀時 | 開（收音＋串流給對方聽） | **聽不到**（對方麥克風被系統關閉，防干擾） |
| 對方朗讀時 | **關**（系統強制靜音） | 聽得到（這是娛樂效果的核心） |
| 回合結算 | 關 | — |
| 結果畫面／賽後 | 開 | 聽得到 |

單機模式沒有「串流給對方」的問題，但同樣沿用「非朗讀者請安靜」的 UI 提示（共用麥克風，干擾會直接影響辨識）。

## 3. 正確率與傷害計算

### 3.1 正確率（accuracy，0.0–1.0）

把語音辨識結果與題目原文比對：

- **中文題**：以「字」為單位。因為繞口令大量同音字、且語音辨識常回傳同音異字（例：「四十四」被辨識成「是十是」），**比對時先把兩邊都轉成拼音（不含聲調與含聲調各算一次）再對齊**：
  - 拼音含聲調完全相同 → 該字得 1.0
  - 拼音不含聲調相同（聲調錯）→ 該字得 0.5
  - 其他 → 0
  - 對齊使用編輯距離（Levenshtein alignment），漏字、多字都算錯。
- **英文題**：以「詞」為單位，先正規化（小寫、去標點、常見縮寫展開），再以編輯距離對齊，逐詞比對；完全相同得 1.0，發音相近的常見誤辨（可維護一張同音詞表，如 they're/their/there）得 0.5。
- `accuracy = 得分總和 / 題目字（詞）數`。

> 注意：語音辨識引擎本身會「自動腦補成通順句子」，這對繞口令是雙面刃——唸得好也可能被腦補成錯字。拼音層比對就是為了吸收這種誤差。此為本遊戲最大的體驗風險，詳見 02 文件 §9。

### 3.2 傷害公式

**【決定】以下數值為初版平衡參數，全部集中放在一個 `balance.ts` 設定檔，方便之後調整。**

```
基礎攻擊力 base = 20（每題固定）
時間加成 timeBonus = 剩餘秒數 / 總秒數 * 5   （最多 +5，逼零分不加成）
完美加成 perfectBonus = accuracy ≥ 0.95 ? 5 : 0

傷害 damage = round(base * accuracy²) + round(timeBonus * accuracy) + perfectBonus
```

- 用 `accuracy²` 而不是線性：讓「唸得爛」幾乎沒傷害、「唸得好」差距拉開，鼓勵好好唸而不是搶快亂唸。
- 每人初始 **HP = 100**。以雙方平均正確率 70% 估算，一場約 8–12 回合、5–8 分鐘。
- 雙方在同一回合都會出手一次，所以不存在「先攻直接斬殺後攻沒機會還手」的問題——**同一回合內，即使先攻把後攻打到 0，後攻仍完成他那次朗讀，同歸於盡則判和局重打該回合**。（替代方案：先攻打死直接結束，較刺激但體感不公平。）

### 3.3 節奏模式的計分（Say the Word on the Beat 類型）

節奏題不比「唸得對」而是比「踩得準」：

- 題目附 `bpm` 與 `beatMap`（哪個字/詞落在哪一拍，見 §6）。
- 播放節拍音軌，玩家要把指定的字唸在拍點上。
- 每個拍點字的判定：以該字的發聲時間點（onset）對拍點的偏差計分
  - ±120ms 內 → Perfect（1.0）
  - ±250ms 內 → Good（0.6）
  - 其他／沒唸 → Miss（0）
- 該次 `accuracy = 拍點得分平均 * 字詞正確率`（唸錯字踩準拍也不算）。
- 傷害公式與一般題共用。

**【決定】節奏模式放在最後一個開發階段（Phase 4）。** 它需要音訊 onset 偵測（Web Speech API 給的時間戳粒度不夠，要用 Web Audio 分析音量突變），技術上最難、又不影響核心玩法驗證。

## 4. 道具系統

**【決定】道具取得方式：開場每人隨機發 3 個，整場用完為止；每回合的道具階段最多用 1 個，作用於「對方本回合的朗讀」。**
理由：規則最簡單、不用做掉落/商店系統；「開局看手牌」也有策略感。替代方案：(a) 每回合隨機補 1 個（拖長戰局）；(b) 依表現獲得（強者更強，不建議）。

初版道具清單（作用對象都是對方的下一次朗讀）：

| 道具 | 效果 | 備註 |
|------|------|------|
| ⏱️ 時間掠奪 | 對方本次倒數 -4 秒 | 不會低於 5 秒 |
| 🔊 噪音干擾 | 對方朗讀時，對方裝置播放干擾音（笑聲、拍手、另一段繞口令） | 音量固定、干擾音不進入辨識（見 02 §7 回音消除說明） |
| 🕳️ 文字遮蔽 | 對方題目文字隨機遮住 25% 的字（變成 ▓） | 遮的是「顯示」，答案判定不變；背不起來就得用聽的（聽先攻唸過的記憶） |
| 💚 回血貼布 | 自己 +10 HP | 唯一作用於自己的道具，上限不超過 100 |

- 道具在「道具階段」雙方**同時秘密選擇**，倒數結束一起揭曉（避免後選的人針對）。
- 兩人對同一人疊加效果時全部生效（例：時間-4 又被遮字）。
- 連線模式下道具效果由伺服器判定與下發（見 02 §6），防止竄改。

## 5. 語言與題目類型

| 類型 | 說明 | 開發階段 |
|------|------|----------|
| 中文繞口令 | zh-TW 辨識 | Phase 1 |
| 英文繞口令 | en-US 辨識 | Phase 1 |
| 節奏挑戰 | 中/英皆可，附節拍 | Phase 4 |

- 建房時可選題庫範圍：僅中文／僅英文／混合／含節奏題。
- 每題有難度 1–5，配對時可選難度區間；同一場不重複出題。

## 6. 題庫規格（資料格式）

題庫是純靜態 JSON（放在 `shared` 套件內，連線模式由伺服器抽題）：

```jsonc
// questions/zh.json 的一筆
{
  "id": "zh-0042",
  "lang": "zh-TW",            // 語音辨識用的 locale
  "type": "normal",           // "normal" | "rhythm"
  "text": "四十四隻石獅子，是死是四十四隻石獅子",
  "difficulty": 3,            // 1-5
  "timeLimitSec": 10,         // 正常語速所需秒數（倒數 = 此值 + 5 緩衝）
  "tags": ["數字", "經典"]
}

// 節奏題additional欄位（type: "rhythm"）
{
  "bpm": 90,
  "beatMap": [                // 哪個字要落在第幾拍（拍從 0 起算）
    { "charIndex": 0, "beat": 0 },
    { "charIndex": 2, "beat": 1 }
  ],
  "audioTrack": "beats/track-a.mp3"   // 節拍背景音
}
```

初版題量目標：中文 30 題、英文 30 題（難度分佈平均）、節奏 10 題。內容於實作階段撰寫，注意避免直接抄襲有版權的當代創作，傳統民間繞口令無虞。

## 7. 勝負與賽後

- 任一方 HP ≤ 0 即敗北；同回合同歸於盡 → 該回合作廢重打（雙方 HP 回到回合開始時）。
- 連線模式對方斷線：暫停 30 秒等重連，逾時判斷線方輸。
- 結果畫面顯示：勝負、每回合正確率折線、最高單次傷害、道具使用記錄。
- 「再來一局」需雙方都按下才開始，重新發道具、重擲先攻；任一方離開則解散房間。

## 8. 攻擊特效（保留給美術）

特效尚未定案（業主表示等美術上線再討論）。架構上的對應做法：戰鬥演出走**事件驅動**——遊戲核心只發出語意事件（`damage-dealt`、`perfect-hit`、`item-used`…），前端有一個獨立的 `BattleFxLayer` 元件訂閱這些事件播放演出。初版用簡單的數字跳出＋血條震動佔位，之後美術素材直接替換 `BattleFxLayer` 的實作，不動遊戲邏輯。
